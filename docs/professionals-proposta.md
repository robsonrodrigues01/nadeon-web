# Proposta para `/professionals`

Os itens abaixo aparecem como `To be confirmed` na rota porque o board os marca
como exemplo ou não fecha os termos. Precisam de aprovação antes de serem
publicados como condições do programa.

| Item                               | Proposta para decisão                                                                                                                                                    |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Desconto profissional              | Definir se haverá desconto, percentual, linhas e produtos elegíveis, limites e cumulatividade.                                                                           |
| Código de indicação e comissão     | Definir existência, percentual, janela de atribuição, pagamentos, mínimo, cancelamentos e obrigações fiscais.                                                            |
| Desconto para pacientes e clientes | Definir se haverá benefício, valor, produtos elegíveis e regras de uso.                                                                                                  |
| Amostras                           | Definir elegibilidade, quantidades, custo de envio e disponibilidade por linha.                                                                                          |
| Materiais técnicos e laudos        | Confirmar quais fichas, fontes de ingredientes e COAs reais podem ser disponibilizados e por lote.                                                                       |
| Treinamento e educação             | Confirmar disponibilidade, formato, frequência e conteúdo revisado.                                                                                                      |
| Elegibilidade e credenciais        | Aprovar profissões aceitas por linha, territórios, documentos aceitos, verificação, renovação e política de retenção dos dados de credencial.                            |
| Prazo de resposta                  | Definir SLA e dias úteis. A página não promete o prazo de 24 horas do exemplo visual.                                                                                    |
| Termos e linguagem permitida       | Redigir e revisar juridicamente os termos do programa, incluindo declarações structure/function, uso de marcas e deveres do profissional.                                |
| Canal de contato                   | Confirmar o endereço do time profissional. O e-mail `pros@nadeonlabs.com` no board está marcado como exemplo; por enquanto, o link leva ao contato existente em `/help`. |
| Estado e território                | Definir territórios aceitos e uma lista de estados ou regiões para substituir o campo de texto atual, se desejado.                                                       |
| Modelo de recomendação             | Confirmar as opções de venda na clínica, código de indicação ou ambos e as responsabilidades de cada modelo.                                                             |

O formulário usa o provider de aplicações existente. A integração live continua
sendo stub até uma tarefa de integração específica.
